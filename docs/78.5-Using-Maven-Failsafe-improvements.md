# Section 13, Chapter 144 (`Sec13_Chap144`): possible improvements

This lecture adds the Maven **Failsafe** plugin and renames the container test from `MySqlTest` to `MySqlIT`. Surefire keeps running the fast `*Test` classes in `mvn test`; Failsafe runs the `*IT` classes in `mvn verify`. So `mvn test` no longer needs Docker. JT's code for it is on his branch `78.5-Using-Maven-Failsafe`.

Versions compared: JT's upstream branch uses **Spring Boot 4.0.6**, this project **Spring Boot 4.1.1**.

## What changed for the test runs

| Command | Runs | Needs Docker |
|---|---|---|
| `mvnw test` | the 21 unit tests (`*Test`, `*Tests`) | no |
| `mvnw verify` | the unit tests, then 20 integration tests: `BeerControllerIT`, `CustomerControllerIT`, `MySqlIT` | yes, for `MySqlIT` |
| `mvnw verify "-Dit.test=MySqlIT"` | the unit tests, then only `MySqlIT` | yes |

Side effect worth noting: `BeerControllerIT` and `CustomerControllerIT` now run automatically in `mvn verify`. Before this lecture they only ran when named explicitly with `-Dtest=...`.

## Improvement 3 in plain English: skipping made sense before, not anymore

In Sec13_Chap142, `MySqlContainerBase` got `@Testcontainers(disabledWithoutDocker = true)`: without Docker, the container test is **skipped** instead of failing. The only reason was that the container test then ran in every `mvn test`, and a missing Docker should not block unit-test runs.

That reason is gone now. Failsafe separates the tests:

- `mvn test` never touches the container, with or without Docker.
- `mvn verify` is the command whose job is to run the integration tests.

So in `mvn verify` the skip does the opposite of what we want: without Docker, `MySqlIT` is quietly skipped and the build stays **green**, even though MySQL was never tested. That is exactly the trap described in the Sec13_Chap142 doc ("the CI server lost Docker - quiet: green build, MySQL never tested").

Removing it makes `mvn verify` **fail loudly** when Docker is missing, while `mvn test` keeps working without it. The split that Failsafe introduced is the protection; the skip is no longer needed.

In practice that means removing the whole `@Testcontainers(disabledWithoutDocker = true)` annotation, not just its attribute: `@Testcontainers` only manages `@Container` fields, and `MySqlContainerBase` has none (its singleton is started in a static block), so without `disabledWithoutDocker` the annotation would do nothing.

## How the top 3 were applied

- **#3** - `MySqlContainerBase` no longer has `@Testcontainers(disabledWithoutDocker = true)`; its Javadoc now says that subclasses fail on purpose without Docker. Verified with Docker Desktop paused: `mvnw test` passes (21 tests), `mvnw verify` ends in **BUILD FAILURE** because `MySqlIT` errors with "Could not find a valid Docker environment" (the two controller ITs still pass), and `mvnw verify -DskipITs` passes.
- **#4** - a pom property `test.jvm.argLine` holds `-javaagent:${org.mockito:mockito-core:jar} -Xshare:off`; Surefire and Failsafe both use `<argLine>${test.jvm.argLine}</argLine>`. Verified with `mvnw -X`: both plugins receive the resolved path to `mockito-core-5.23.0.jar`, and `clean verify` runs without warnings.
